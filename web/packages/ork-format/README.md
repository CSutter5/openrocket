# Expanded ORK feasibility proof

This package runs a bounded desktop-compatible archive edit in the browser without replacing the desktop loader. It retains the original upload and exact ordered entry bytes, strictly parses UTF-8 XML, and replaces only a selected component's name text after checking its UUID and previous name. All other XML bytes, including unknown subtrees, namespaces, numeric precision, configuration references, scripts, expressions, document preferences and stored flight series, remain untouched. Imported scripts are never executed. The package uses SI values only indirectly through preserved XML; it does not reinterpret numerical fields or validate a complete component graph.

`importArchive(Uint8Array, optionalSidecar)` returns an expanded archive, editable/preservation mode, diagnostics, and an identity sidecar. `componentNames` exposes the bounded editing projection. `renameComponent(archive, componentId, expectedName, name)` returns a new archive or an explicit conflict. `exportArchive` returns `{bytes, identity}`; unchanged imports return original bytes, changed exports use deterministic ZIP ordering/compression/timestamps with `rocket.ork` first. The sidecar is never inserted into desktop files. These package APIs are narrower than the shared future codec contract; uppercase error codes are package-local diagnostics.

Simulation identities are generated UUIDs in the sidecar, distinct even when names/configurations repeat. A sidecar is accepted only for its exact archive hash, supported schema, simulation count and unique valid UUIDs. App edits retain the mapping. A desktop re-save changes the archive hash: `SIDECAR_RECONCILIATION_REQUIRED` reports the loss and creates fresh identities, without guessing by name or configuration. Component names can still be edited independently of those mappings. Cross-desktop identity reconciliation is not implemented.

## Reproduce

From the repository root, after installing the locked web workspace dependencies:

```sh
npm test --prefix web/packages/ork-format
./gradlew -I web/packages/ork-format/jvm/classpath.gradle :core:orkProofClasspath -Dork.proof.classpath=/tmp/ork-proof-classpath.txt
ORK_PROOF_CLASSPATH="$(cat /tmp/ork-proof-classpath.txt)" node web/packages/ork-format/test/desktop-proof.mjs
CHROMIUM_EXECUTABLE=/path/to/chrome node web/packages/ork-format/test/browser-proof.mjs
```

Java 17, Gradle 9.8.2, Node 26.13.1, Playwright 1.61.1 and esbuild 0.28.2 were used. Java and the Node HTTP harness are development-only. The browser codec bundle has no Node imports. The desktop bridge reuses the existing `OpenRocketSaverTest.setup()` injector with its small motor database; the three example motor curves must therefore resolve from the embedded RSE data when absent in that database. The bridge runs actual desktop Java loader/saver code headlessly. No Swing GUI or production deployment was exercised. Browser and desktop commands create only local `/tmp/openrocket-ork-*-proof` artifacts by default.

## Boundaries and remaining work

The corpus maximum is 898,630 uploaded bytes, 2,769,418 XML bytes and 11 entries. G1 limits provide bounded headroom: 4 MiB upload, 16 MiB expanded total, 8 MiB per entry, 64 entries, depth 64, 100,000 XML elements and 1,024-character names/paths. Central/local ZIP headers and data descriptors, file order, bounds, paths, compression and CRCs are checked before use. Deflate/GZIP input is fed in 1 KiB chunks; decompressed bytes are checked before retaining output. A lying declared ZIP size fails during inflation rather than allocating an unbounded result. CPU and peak memory at these limits remain unmeasured.

ZIP64, multidisk, encrypted/non-deflate ZIP, directory entries, non-UTF-8 XML and ambiguous legacy filename encodings are explicitly unsupported. Historical/future formats and missing/ambiguous component IDs can be preserved/downloaded but cannot be edited; legacy ID allocation is deferred. Unknown XML and files survive the supported name edit, but no structural/numeric/asset-replacement editing API is provided. Arbitrary unknown content has no execution parity claim. Images remain opaque and are never rendered: dimensions and image-decoder safety need proof before display. Import warnings for broken motor/decal references and full numerical/graph validation are deferred to the model integration. An unsupported absolute path in an existing official example remains a concrete compatibility limitation; investigate a safe opaque archive-path representation before relaxing rejection.

The [generated format-1.11 report](evidence/format111.json) repeats the JVM/web round trip after the current desktop saver enables RK6 and fixed seed 8447 on the first simulation. Those settings survive both directions. This fixture deliberately retains the imported historical flight data; it does not certify those results as runs of the changed options. The generator and assertions run automatically with `test:desktop`. Review also added preservation-only handling for comments/processing instructions inside a component name, so an edit cannot silently discard them.

The file proof establishes this bounded edit path, not full T02 or desktop parity. Next investigations are archive-safe absolute-resource handling, historical ID allocation/reconciliation, model-command effect application into XML, and codec memory/CPU measurements in workerd. Full G1 assessment belongs to the coordinator's combined evidence record.

## Imported radius edits

`src/radius.js` adds a bounded explicit-radius projection and effect adapter; the public name-edit API remains unchanged. `tubeRadiusInput` extracts the component UUID, length, numeric radius, thickness/filled state and bulk density from authoritative XML. Automatic radii, ambiguous or missing fields, invalid dimensions and unproven stored-result statuses refuse the edit. The original proof refuses presets; the bounded two-record support below extends it. The TypeScript declarations describe the existing codec and this narrow projection.

`applyTubeRadius` consumes accepted Java effects. It replaces only the radius/thickness text and necessary stored-result status values, preserving other XML, IDs, attachments, identity sidecar and original upload bytes. It never calculates mass or substitutes its own setter. `radiusSimulationEffects` exposes invalidations for the server acknowledgment. Full archive-hash preconditions are required at the command boundary, since intrinsic scalar inputs alone do not cover the document. Eight codec regressions now run with `npm test`, including stale inputs, unsupported content, filled tubes, no-ops and status-like text inside an opaque attribute.

The initial radius/thickness-only desktop comparison failed: the real Java setter also made two simulations outdated. The corrected codec marks supported stored results outdated while retaining every byte of their `flightdata`. A Java no-op retains the original archive and statuses. Mass/CG overrides remain unchanged opaque XML; returned mass/CG values are intrinsic component properties. `RadiusDesktopProof.java` compares the actual loaded document's setter with the web export, then desktop save/reload and every resolved motor curve. Its semantic comparison is the headless loader/saver projection; lexical comparisons separately protect unknown fields and result data.

See the [authenticated Workers integration and reproducible command](../../platform-proof/README.md#authenticated-imported-radius-proof) for the supplied file, failure evidence and exports. Both radius cases preserve 17 components, six simulations/5,540 stored points, five motor assignments and all archive attachments. Full component/preset catalogs, imported extensions, Swing interaction and arbitrary numerical edits remain unproved.

## Preset references and configuration-dependent effects

The radius projection now supports the two exact `PROOF_PRESETS` records, including manufacturer, part number, type and digest. Unknown catalog records, ambiguous references, references after scalar fields, and automatic geometry dependencies outside the one-ring subset below refuse editing explicitly. The trusted Java effects include actual preset identity before/after, intrinsic geometry/mass/CG/volume and listener count. A changed radius removes precisely the preset element; a no-op retains the original bytes. Non-preset radius behavior remains covered by the earlier proof.

`src/deployment.js` projects one identified parachute's default event/altitude/delay, every complete override, ordered flight configuration IDs and all simulation configuration references. A reset removes only the selected override and uses the Java functional-change decision to invalidate results for that configuration. Every simulation sharing that configuration is covered. Equal-to-default override removal leaves result statuses alone; inherited resets retain the original bytes. Partial, duplicate, opaque or wrongly ordered overrides, unknown configurations, invalid parameters and unresolved simulation references refuse editing. Unknown XML outside the removed override remains lexical data. Override comments, attributes and unknown children are refused because removing their enclosing element would lose them.

Five additional Node regressions exercise these boundaries, stale inputs, lexical preservation and selective invalidation. `ImportedEffectsDesktopProof.java` generates real desktop fixtures, resolves actual preset records, compares complete relevant JVM/Workers state and full desktop serialization, then saves and reloads each of ten exports and compares all motor curves again. The fixture derives from the official simple rocket and retains 13 components, two decals, five motor assignments and six historical simulations with 3,014 points (one simulation is duplicated to share a configuration). Two generated variants vary preset geometry/density and deployment defaults. Their result series are unverified imported data, not fresh runs of the modified designs. A throwing imported script remains preserved data; desktop import disables it through its ordinary trust behavior. Unknown namespaced XML and a binary attachment are separately checked lexically.

See [commands and evidence](../../platform-proof/README.md#imported-preset-and-configuration-proof). Full imported-graph construction, mutable preferences, general catalogs, other configuration operations and desktop sidecar reconciliation remain open G1 work. No Swing UI or flight rerun is claimed.

## One automatic centering-ring dependency

`tubeRadiusInput` now recognizes one direct child centering ring with `<outerradius>auto</outerradius>` and an explicit inner radius. Its preconditions include the identified parent relationship, ring length/density/inner radius, matching current/legacy TOP position fields, centered position, one instance with zero separation, and imported flight configuration IDs. A preset-backed tube may have this one automatic dependency. Other automatic fields, nested/extra automatic components, ring presets, unknown/ambiguous position forms, and unfitting source geometry refuse the command. The projection remains available after the tube's preset clears; later edits still execute the two-component Java facade.

Accepted effects preserve every ring XML byte, including its automatic token, materials, comments and unknown fields. The server acknowledgment separately identifies the ring and its actual derived geometry. Growth and fitting shrinkage only replace the supported tube fields/preset span and affected simulation statuses. Four additional codec regressions cover projection/preconditions, repeated edits after preset clearing, unsupported geometry forms and rejection of unsafe or incomplete effects.
