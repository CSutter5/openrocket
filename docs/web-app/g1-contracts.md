# G1 contracts and selected inputs

These are version 1 feasibility boundaries for T01–T03, not an application schema or a claim of complete T00 discovery. The pinned desktop source is `33bdb6d3062a6d9ef44a00d1ff865f962136e9e9` (26.11.beta.01). Java source changes after that revision must be reviewed separately. No production resources or external compute are needed by these proofs.

## Shared boundaries

`web/packages/contracts` defines protocol/model version 1, the initial command envelope, diagnostics, archive and identity representations, and completed-result provenance. Rocket dimensions use SI, angles use radians, desktop IDs remain strings. XML and archive entries plus a versioned identity sidecar are authoritative; projections are reconstructible. The proof packages may have narrower local entry points; an unintegrated command example is not a claim that the collaboration protocol works.

A command includes project/branch, epoch, operation ID, observed sequence and expected values for the reducer's complete read/write effect set. The authenticated server supplies its author and accepted sequence. It cannot trust a submitted replacement snapshot. Setters execute on request-local Java documents; process-global preferences cannot be swapped between projects. Each reducer must publish its supported operations and reject everything else. Bound effects include automatic dimensions, thickness, presets, listeners and graph/configuration changes where applicable. Until that effect set is established, concurrent acceptance is unproven.

Independent edits use separate entity/field preconditions and may succeed with an older observed sequence when all expectations still match. Two edits expecting the same old value conflict after the first acceptance. A reconnect supplies epoch and last sequence; a changed epoch or missing tail requires `resync`, never blind replay. Unsupported protocol negotiation fails explicitly. This milestone specifies these examples; durable collaborative implementation remains T07.

An archive codec imports bytes into exact ordered entries and keeps original bytes. Unchanged download returns the original. Edited ZIP output places `rocket.ork` first and excludes web metadata. The file proof specifies its concrete API and bounds beside its tests. Unknown XML/attachments remain intact, and editing that cannot preserve their meaning is refused or limited to preservation mode. Desktop component/configuration IDs are retained; web simulation identities are separate from configuration IDs. Reimport without the sidecar must not silently merge ambiguous simulations.

A simulation input manifest binds exact archive-tree and sidecar hashes, configuration/simulation IDs, options, seed, integrator, engine, motor/material catalogs and extension set. The contract hashes a domain-separated fixed-order encoding; it does not normalize XML. Completed output is attributed to a browser client and remains attached to that immutable input. A late completion cannot become a result of a newer input. Reading a saved result requires project authorization independently of knowing its hash. The contract tests cover stale classification; result upload/sharing is outside this milestone.

## Bounded imported command integration

The [radius integration](../../web/platform-proof/README.md#authenticated-imported-radius-proof) now connects the earlier proofs for one explicit BodyTube. The authoritative archive is parsed on each request; no client projection/effects are trusted. The Java facade receives only intrinsic length/radius/thickness/filled/density, calls the actual setter and returns intrinsic effects. Preset/automatic/ambiguous source forms refuse the edit. Mass/CG overrides remain opaque XML and are excluded from those intrinsic metrics. Full-document JVM comparison identified the additional stored-result invalidation; the codec changes supported simulation statuses to outdated while preserving raw data. Accepted effects name those web simulation IDs, distinct from motor configuration IDs.

This proof uses the shared `Command` envelope with exact observed sequence, all intrinsic preconditions, automatic/preset expectations and a whole-archive hash. The hash conservatively protects dependent/unknown fields and statuses; it intentionally does not establish independent-field concurrency. After async authorization/blob work, SQLite rechecks the source revision and atomically publishes archive bytes, sidecar, sequence and deduplication result. Original/revision blobs are private R2 objects; exports omit web metadata. A competing request can leave an unreachable blob but cannot overwrite the winning state. Only one branch/epoch and 32 accepted operations are supported. Full graph projection, mutable preferences, imported configuration listeners, broader preset semantics and the later repository protocol remain open.

## Preset and deployment-reset command boundary

The [next imported proof](../../web/platform-proof/README.md#imported-preset-and-configuration-proof) extends the existing endpoint and envelope with `resetDeploymentConfiguration(componentId, configurationId)`. Its read set is the authoritative parachute default, all overrides, ordered flight configuration IDs, all simulation-to-configuration references and statuses, component identity, sequence and complete archive hash. Its writes remove only the selected override, change its effective/default-alias relationship, and update the selected flight configuration's modification state if parameters changed. The event also changes the rocket's document, aerodynamic and functional modification IDs, while leaving its mass/tree IDs unchanged; these changes are compared relative to each runtime's pre-command IDs. Every current stored simulation using that ID then becomes outdated. Other configurations, motor assignments and raw results remain intact. Equal-valued override removal and inherited no-ops emit no functional event.

Preset radius commands additionally require an exact two-record catalog identity (type/manufacturer/part number/digest), saver-compatible field order and explicit geometry or the supported ring dependency below. Accepted Java effects retain the real preset for an equal radius or clear its reference for a changed radius. The supported scalar read set and document-wide radius invalidation remain as above. Unknown preset records and unsupported configuration forms reject commands without publishing changes. Source archive hashes still conservatively cover dependent/unknown content; independent-field concurrent acceptance is not established.

Both commands share private R2 publication, the same SQLite source-revision check and the transaction-level duplicate-operation recheck. No new repository, deployment or history protocol is introduced. The state response now reports per-simulation statuses; accepted no-ops alone do not label the historical results stale. Process-global preferences remain immutable fixture policy, with mutable user/document defaults explicitly unproved.

## Automatic outer-radius ring dependency

The automatic-ring follow-up retains `setOuterRadius` and the existing protocol/model versions. When the authoritative projection finds the supported child, its complete preconditions additionally include `ring` (component/parent IDs, explicit inner radius, length/density, matching TOP position, centered radial values, one instance/zero separation) and ordered flight configuration IDs. The whole archive hash continues protecting other graph fields, simulation statuses, references and opaque content. This is a two-component dependency projection, not independent-field concurrency or full imported graph construction.

| Relevant state | Read set | Accepted effects |
| --- | --- | --- |
| BodyTube | Existing explicit geometry/material/preset inputs | Real radius setter, thickness/automatic/preset effects, intrinsic mass/CG/volume |
| CenteringRing | Identified direct parent; `outerradius=auto`; explicit hole, material, length, position and instances | Actual derived radius/thickness, mass/CG/CG weight, inertias and bounds; automatic token and all other ring XML stay unchanged |
| Event/result state | Imported configuration IDs, complete archive revision and stored-result statuses | Document/mass/aerodynamic/functional root IDs and every configuration's ID change for a functional radius edit; tree ID stays unchanged; supported current stored results become outdated |

The Java scene is request-local and uses the original getters/event path. Explicit inner radius excludes sibling lookup, and a cylindrical parent excludes variable-radius dependencies on the rest of the graph's absolute positions. Multiple/other automatic geometry fields, ring presets, non-TOP or mismatched legacy positions, off-center/multiple instances and invalid parent fit refuse editing. Accepted effects identify the ring separately as `derivedGeometry`; no client projection or effects are trusted. The same path remains required after the tube preset clears.

An edit producing a ring outer radius below its explicit hole is rejected before revision publication: the pinned desktop loader disables automation on reopening that live state. The [desktop control and diff](../../web/packages/ork-format/README.md#one-automatic-centering-ring-dependency) retain the failure. No baseline change or silent correction is authorized by this rejection. Membership/revision checks, the transaction-level retry recheck, private R2 publication and SQLite atomic acknowledgment are unchanged.

## Sibling-dependent automatic inner radius

The next bounded input retains the radius command, archive transaction and explicit-hole rejection above. A both-automatic ring additionally projects `innerAutomatic: true`, `precedingNoseLength` and `sibling` under `ring`. The numeric `innerRadius: 0` is the reconstruction seed, not a calculated hole. `sibling` contains its component/parent IDs, explicit outer radius/thickness/length/material density, matching current/legacy TOP offset, zero radial position/direction and single cluster configuration/scale/rotation. These are authoritative archive-derived preconditions, including after preset clearing; a submitted snapshot never supplies authority.

The pinned `CenteringRing.getInnerRadius` resets its stored inner radius to zero on every automatic read, walks every direct child of its parent, considers only `InnerTube` siblings, and obtains the ring's two endpoint coordinates relative to each sibling using `toRelative(...)[0]`. It excludes a sibling only when the end is strictly before zero or the start is strictly beyond the sibling length. Both exact endpoint contacts therefore count. It selects the maximum outer radius of qualifying siblings and caps that value with `getOuterRadius()`. The latter reads the parent's inner radius at the two clamped ring endpoints and writes the cached outer radius; a cylindrical explicit BodyTube reduces that radius to its filled/thickness/outer-radius inputs. The inner read writes the cached inner radius without firing an event or changing automation. Ring thickness, intrinsic mass, CG/CG weight, inertias and bounds read those derived radii. Sibling intrinsic mass/CG/inertias exclude its motor and explicit descendants; those remain preserved archive content.

`toRelative` reads the first source absolute location and the first destination absolute location, including ancestor positions and instance offsets, before subtracting. The proof cannot discard that common prefix merely because it cancels algebraically: floating-point endpoint comparisons can depend on it. The supported graph is one direct axial stage with a zero-position root, an explicit AFTER nose cone followed by the AFTER BodyTube, stage/configuration references unambiguous and the sole stage active. Java reconstructs the nose length before adding the tube. Other prefixes/stages/positioning refuse editing. Ring and sibling are centered TOP single instances, wholly within the parent's length; the sibling has explicit geometry, no preset and the exact single cluster. Other automatic fields anywhere in the document, multiple/missing siblings, malformed/duplicate fields and mismatched legacy positions refuse commands. The existing explicit engine-block descendant and motor assignments remain XML data; they do not participate in the getter's read set.

The accepted setter still writes the tube radius, automatic flag, thickness clamp and preset identity; its ordinary event updates document/mass/aerodynamic/functional modification IDs and all flight-configuration IDs, leaving the tree ID unchanged. The codec writes only tube radius/thickness, a cleared preset reference and affected stored-result statuses. Both automatic ring tokens, sibling XML, component identities/parents, configuration/motor references, attachments, unknown/script XML, sidecar identities and historical result series remain exact. Root/per-configuration event effects and primed/repeated geometry are compared against the actual loaded desktop document. Global preferences remain immutable fixture policy; arbitrary user/document defaults are still an isolation gap. No imported script or server simulation runs.

Unlike the explicit-hole input, an automatic hole can shrink with the outer cap. Positive and zero cap cases require their own full serialization/reload evidence; the explicit-hole underfit refusal must remain. Protocol/model version 1, strict sequence/whole-archive preconditions, private R2 blobs, SQLite publication and the transaction-level deduplication recheck are unchanged. This is an extension of the G1 proof, not T04–T13 or a general graph importer.
