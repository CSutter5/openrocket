# One shared rocket POC

The November 20, 2026 request authorizes a bounded collaboration increment: everyone edits one file and enters a display username. Accounts, authentication, application logging and version history are excluded. This supersedes the local-only restriction for this increment (ADR-26); broader G1/G2–G7 gates remain held. Existing authenticated platform proofs are unchanged.

## Run and try

Build with `npm run build:app --prefix web`, then run `npm run preview:cloudflare --prefix web`. Open `http://127.0.0.1:8787` in two browsers or independent browser profiles and enter different usernames. Both join the same room; there are no project IDs or separate rooms to choose. The first visitor initializes the room with the bundled rocket sample. The participant list shows connected sessions, including duplicate display names if supplied.

Rename a component, apply a dimension or save a component dialog in one browser and observe the other. Component creation/property/tree actions and motor/configuration changes use the same commands as the existing local editor. Selection, units, flight-configuration selection and newly calculated flight results remain browser-local. New and Open replace the shared file for everyone. Download creates a local `.ork` copy with no collaboration metadata. Reloading asks for a username again and rejoins the current draft.

The room stores only its latest draft, including opaque assets and the existing simulation identity sidecar, in SQLite-backed Durable Object storage. It acknowledges changes after that storage transaction succeeds. This is current-state persistence, with no command log, revision list, accounts, D1, R2 or application telemetry. Wrangler's development console output is separate from application logging. Local preview data stays in Wrangler's local persistence directory. No deployment or remote resources were created for this task.

## Command and recovery contract

`/api/coedit` advertises shared mode; `/api/coedit/socket?username=…` connects to the single `everyone` object. Usernames are trimmed display names of 1–40 characters, never authenticated identities. The browser sends commands and an opaque token identifying the draft it has received. The room serializes commands, checks the token and executes the existing archive/reducer handlers itself. It accepts whole archives only for the explicit Open operation; arbitrary state-sync messages are refused. Same-origin upgrades are required.

Every accepted operation replaces the current snapshot/token in one transaction, then broadcasts the exact archive bytes, sidecar and filename. Archive bytes are stored in 64 KiB chunks to respect storage value limits, with a 4 MiB shared draft limit matching the codec's upload bound. There is no retained command history or automatic replay. A stale command rejects explicitly, including independent edits submitted against the same older token; field-level concurrent merging is deferred. A duplicate command with an old token cannot apply twice. This deliberately narrower POC differs from the full ADR-03 protocol.

Clients publish views only after importing the server snapshot in their document Worker. Failed commands/imports leave the accepted draft unchanged. External updates preserve component selection by UUID and retain open component-dialog drafts. A stale dialog shows a notice and refuses submission; copy the draft before closing and reopening against the latest file. Motor and component-insertion pickers close on external updates, since their choices depend on the replaced document. A reconnect disables editing, rejects any outstanding request with an unknown-outcome message, then imports the latest draft. It never automatically replays an operation whose outcome may already have been saved. Hibernating sockets retain only their display-name attachment; the latest draft is reconstructed from storage, following [Cloudflare's hibernating WebSocket API](https://developers.cloudflare.com/durable-objects/best-practices/websockets/).

The document session was extracted from `document.worker.ts` so the server and browser use the same command handlers. View/stability construction remains in `document-view.ts`; the server bundle uses the smaller Java reducer and does not run flights or import the full flight engine. Motor commands load verified catalog curves through the static asset binding. The plain Vite development/preview server retains the existing browser-local workflow when the shared API is absent; use Wrangler for coediting.

## Verification and handoff

`npm run test:coediting --prefix web` builds/typechecks, dry-runs Wrangler, and runs `web/app/test/coediting.mjs` against a fresh temporary local storage directory. It uses two independent Chromium contexts and additional protocol clients. The test checks participant presence, shared rename/radius edits and identical exports, concurrent same-state conflict, invalid radius/import/sync/stale-tree refusal, duplicate/delete convergence, retained stale component drafts, exact opaque-asset preservation across multiple storage chunks, participant disconnect, editing disabled during disconnect, a full local runtime restart, automatic reconnect and a late join receiving the same saved bytes.
