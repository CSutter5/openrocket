This follow-up addresses the reported refusal of `example rocket.ork` after checkpoint `3230c6367`. Saved desktop simulations are no longer themselves a reason to reject a new local flight. The browser reconstructs the accepted archive's supported rocket, internal components, configurations, materials, overrides, motor data and recovery in Java. It does not run the unrelated fixed `EngineProof.flight` fixture. Broader G1/G5 and arbitrary desktop compatibility remain held. [Compact numerical evidence and artifact hashes](imported-browser-simulation-evidence.json) accompany this record.

The original [flight-ready sample](../../web/app/public/flight-ready.ork) and its synthetic C6 curve remain available. Imported format 1.11 files can use one direct active axial stage, at most 64 components, 1–16 explicit configurations with exactly one default, one motor mount and one or two parachutes. The default configuration is runnable; configuration selection/editing is deferred. Supported component types are rocket, stage, nose cone, transition, body tube, single inner tube, trapezoid fins, mass component, parachute, bulkhead and shock cord. Supported shell shapes are conical, ogive, ellipsoid, power, parabolic and Haack, with the corresponding saved parameters. The importer requires explicit native physical fields and checks allowed fields/attributes; automatic radii, positioning, fin geometry, material densities, mass/CG/CD and subcomponent overrides, ignition/ejection and deployment overrides are reconstructed through core setters. Unsupported components, clusters, ambiguous paired positions, unresolved references, extensions, scripts and unrepresented behavior fail visibly while file viewing, preservation and supported edits remain available. This is a bounded importer, not a promise that every combination of those component types is numerically certified.
