# Imported desktop metadata and explicit physical state

The November 20, 2026 follow-up reports missing geometry/statistics and “Simulation unsupported: Unsupported document preferences” for the same `L00k 50k 3in to 2in.ork` used in the [archive-size fix](archive-size-limits.md). The first rejection is the desktop `simulation.table.hiddenColumns` display preference. Further inspection finds optional landing-dispersion setup, personal parachute preset references and per-motor nozzle exit diameters. All four must be represented appropriately to enable this file's preview and ordinary saved flights. Custom expression definitions and original stored channels remain preserved under the existing imported-flight contract.

## Decision and boundaries

ADR-38 accepts the known hidden-column preference as a scalar `<pref key="simulation.table.hiddenColumns" type="string">`. It controls only the desktop simulation table, as shown by `SimulationPanel.ColumnVisibilityController`; it does not affect native physical calculations. The browser retains its exact archived value without applying it to account preferences or runtime engine globals. Unknown preference keys/types, attributes and nested values remain refused.

An optional per-simulation `landingdispersion` element is a separate analysis setup, as shown by native `Simulation.getLandingDispersionSettings`, `LandingDispersionSettingsHandler` and `MonteCarloSimulationRunner`. The ordinary flight path does not execute it. Accept one bounded native-shaped setup: integral run count 2–100,000, signed 32-bit seed, unique known uncertainty parameters, supported normal/uniform/log-normal distributions and finite nonnegative spreads. Log-normal distributions require native relative parameters. Preserve this setup without starting a dispersion analysis or changing nominal conditions. Malformed/unknown analysis behavior and imported scripts/extensions remain refused. This adds no browser landing-dispersion feature or expression evaluator.

Unknown personal parachute presets follow the explicit saved-state approach already used for rail buttons (ADR-36). Require a nonempty manufacturer/part number, a `PARACHUTE` type and a bounded hexadecimal library reference, plus explicit packed dimensions, CD, material, canopy diameter, line count/length/material after the preset reference. Any serialized mass/CG/CD override must also follow the reference, with both its value and subcomponent flag present. The supplied archive has historical 31-digit references, retained as opaque library identifiers rather than trusted preset resolution. Physical reconstruction consumes the subsequent scalar fields through native setters and preserves the library link in the archive. The existing exact pinned parachute-preset path remains intact. Missing, late, invalid or ambiguous physical state is refused; no arbitrary preset catalog entry is installed.

Nozzle exit diameter affects powered base drag and cannot be treated as display metadata. Accept the optional scalar field in each motor assignment, validate it against zero and the saved motor casing diameter, carry it into the model input and call native `MotorConfiguration.setNozzleExitDiameter` after assigning the resolved motor. That native setter also checks the actual motor diameter. Absence retains the native zero/unknown value. Preserve catalog-before-embedded motor resolution, all per-configuration ignition settings and the original archive. No desktop algorithm or pinned core source changes are made; rebuild both existing TeaVM targets and retain original/adapted JVM checks.

Removing only the initial preference guard would reveal further refusals and would omit a real physical nozzle input. Dropping metadata, presets or nozzle fields from the file would violate preservation or alter behavior. This bounded projection instead distinguishes the specific known display/separate-analysis data from fully specified component and motor inputs. Broader document preferences, arbitrary presets, expression execution and Monte Carlo UI remain outside this task.

## Verification and handoff

`web/app/test/DocumentMetadataDesktopProof.java` generates an independent native two-stage fixture containing a registered parachute preset with positive mass/CD effects followed by explicit overrides, the hidden-column preference, landing-dispersion settings and nonzero nozzle diameters. The reference loads that real preset, checks the post-preset fields, and proves that clearing only library links leaves the physical snapshot unchanged. It compares complete reconstructed rocket/configuration serialization with the independently loaded desktop model, including every motor's nozzle field. Only appearance and unordered recovery-map serialization are normalized, following the existing rail-button oracle. Physical values are never normalized.

`web/app/test/document-metadata.mjs` runs that fixture and an optional local user archive in actual Chromium workers. It compares preview dimensions, mass, CG/CP and exterior/internal geometry at 1e-10, all named flight branches and source-identified events, and saved-condition browser trajectories against native JVM flights. The generated fixture and six two-stage user configurations retain 1 ms/0.12 m/0.25 m/s/3 m/s² sample bounds and 1 mm/1e-6 m/s/1 ms summary bounds. Scheduled launch/ignition/burnout/ejection/separation times use 1e-10 s throughout. Equal integration grids are compared by matching rows; unequal grids use bidirectional interpolation. The former avoids artificial interpolation across a parachute-deployment acceleration discontinuity. Unknown/malformed preferences and dispersion settings, incomplete/late parachute state, invalid nozzle sizes and scripts remain refused with disabled Run actions and exact downloadable originals.

The user explicitly directs accepting small numerical differences after the approximately 7 mm apogee and 0.06 s landing-time differences in a single-stage configuration were reported. Two named optional-user cases (`46ba2526-b5a1-4e66-aee3-768cf0ca0837` and `8b54ad13-e29d-452a-8417-c424f4f02f9f`) use an explicitly scoped sampling profile: 0.25 m apogee, 1e-5 m/s maximum speed, 0.05 s apogee time and 0.5 s landing time. Event types/sources/order and scheduled events retain their strict checks; other event times allow 0.5 s. For unequal grids, compare corresponding event intervals with at most 0.5 s alignment, retaining 0.25 m/s speed, allowing 3 m altitude variation around recovery threshold sampling and using the established long-C6 corpus allowance of 20 m/s² for acceleration interpolation near a sharp thrust tail. Native `AbstractEulerStepper.RECOVERY_TIME_STEP` is 0.5 s; the time allowance is one recovery step and the altitude bound is tighter than one terminal-descent step at approximately 7 m/s. The largest acceleration interpolation difference occurs just before the HP-L1000W's 3 s burnout. This is a recorded fixture-specific numerical limit, not a general accuracy claim or a change to simulation algorithms.
