# Component properties and tree actions

The November 19, 2026 follow-up authorizes editing every value displayed in Imported properties, enabling Move up/down, Duplicate and Delete, and reducing the CG/CP symbols without their visible text labels. This supersedes the creation-only editing limits in ADR-23 and the previous component-creation handoff. ADR-24 records the change. Accounts, hosted state and general desktop/physics parity remain outside this local editor slice.

## Editable archive values

The editor shows the component name first. For components outside the older explicit BodyTube controls, Imported properties opens immediately with editable values. Existing BodyTube quick controls remain available where their established proof applies. Fields no longer truncate at 200 characters. Each previously displayed scalar XML field has a form; its existing attributes are editable too, including material density and position methods. Component IDs and hierarchy containers stay outside this panel, and names retain their existing control. This does not add a general nested XML editor, absent-property creation, a part catalog or a motor-mount configuration dialog.

Build-time generation reads the pinned desktop `DocumentConfig` setter metadata for field kinds, enumeration choices, automatic/filled tokens and material types. Runtime validation checks decimal numbers, booleans, counts, methods, color channels, material names/types and XML characters before replacing the selected leaf. Native fin counts remain 1–8; other instance counts use the local editor's bounded limit of 64. Archive units remain explicit: meters, degrees and kilograms, rather than guessing units from field names. Each Apply button commits one property; invalid submissions retain the accepted document. Unknown scalar fields remain editable XML text. A valid archive edit does not certify arbitrary imported physics or setter side effects for every component.

Current/legacy position, fin-count and angle representations stay synchronized. Tube-fin repeated saver fields update together. Enabling an automatic radius retains its existing cache when the native format accepts one. The established Java BodyTube wall/radius clamps are reused for explicit dimensions, and known preset metadata is cleared for relevant material/dimension changes. The existing radius/ring validation is now exposed separately from its older result-status proof, so the raw radius control still rejects the proven automatic-ring hole-underfit case. The older quick-control proof and its refusal tests are unchanged. Unsupported geometry or flight inputs continue to report an explicit reason; broad raw-field editing does not expand the engine's component/graph support.

All edits capture the accepted archive hash, target component UUID and field index. Changes pass lexical span replacement, archive export/reimport, identity-sidecar validation and view construction before publication. Unchanged values retain exact bytes. XML text and attributes are escaped; imported strings, expressions and scripts are never executed.

## Component tree behavior

Move up/down swaps the selected component with its adjacent sibling, carrying its entire subtree. Duplicate appends a deep copy to the same parent, retaining names, properties, motor/recovery configuration links and attachment references while assigning fresh UUIDs to every copied component. This matches the desktop duplicate placement. Delete removes the selected subtree and selects the next sibling, previous sibling or parent. Tree actions close the component editor and preserve selection by UUID, including when names repeat. The root cannot be moved, duplicated or deleted; the last direct axial stage cannot be deleted. The existing 64-component cap remains.

Configuration stage flags follow stage UUIDs through moves, duplication and removal, then serialize under the resulting native stage numbers. New copied stages start active. If deletion removes the last active stage in a configuration, stage zero becomes active, matching `MotorConfigurationHandler`'s desktop reload rule. Without this normalization, native reload silently changes the accepted configuration. Simulation UUIDs, configuration IDs and surviving component IDs remain stable.

Physical/tree edits mark up-to-date, loaded and external stored results outdated while retaining all settings, events, series and assets. Native cannot-run, aborted and not-simulated states remain preserved. This explicit new-action status handling is needed for legitimate inactive-stage archives; it does not weaken the older radius proof's narrower invalidation contract. Unknown result statuses still refuse. Component creation shares this status handling so creation continues to work after the newly enabled stage actions.

## Drawing and verification boundary

CG/CP symbols use the existing distinct colors and shapes at 75% of their previous size. Visible CG/CP lettering beside the symbols is removed; accessible names, axial positions and the numerical information remain. Fin rotation in the drawing now converts the archive's degrees to the native getter's radians, which is necessary once the rotation field can be edited. Native physics algorithms and engine adapter sources are unchanged.

`component-editor.mjs` checks smaller unlettered markers, enabled controls for every displayed scalar/attribute across all 21 component types, immediate automatic-tube editing, representative native field edits, long multiline comments, invalid-input retention, subtree actions, stage activeness, stale requests and preservation-only inputs. `ComponentDesktopProof` applies actual desktop import setters and native move/copy/remove operations, compares native serialization and saves/reloads the results. It uses native save/reload as the deletion reference when the last active stage is removed.

Deletion has an existing desktop I/O limit: retired historical event/warning sources become the native REMOVED sentinel on desktop reload, warning labels are regenerated, and automatically registered orphan material definitions can differ from the original archive's explicit preferences. The browser preserves those original historical XML values and explicit preferences. Deletion comparisons therefore normalize only retired source references/their derived warning text and the separate document-material catalog; independent lexical assertions require exact archived simulation contents, preferences, opaque XML and attachment hashes. These deletion checks prove design/configuration parity and archive preservation, not byte-identical historical metadata through a desktop re-save. No desktop core fix is bundled into this UI work.

Generated schemas, reports, downloaded archives and screenshots remain in ignored `web/app/build/`. The existing user archive and root `.wrangler/` are not fixtures or owned changes. No new dependencies, backend services or deployments are introduced.
