# Motor configurations and the saved simulation workspace

The subsequent [tube motor-mount controls](motor-mount-controls.md) (ADR-31) supersede the mount-creation deferral below; catalog configuration uses tubes enabled in the component dialog.

The November 19, 2026 user follow-up authorizes removing the explanatory/manual controls and Session flight row, making motor selection catalog-only with desktop filters, and implementing New, Rename and Delete configuration. This supersedes the manual UI descriptions in ADR-17/20/21 and the earlier workflow records. Existing saved settings, graph support, preservation rules and browser-only result storage remain in effect. ADR-22 records the updated contract.

Flight simulations now contains the document's actual rows, compact Run flight / Plot / Cancel flight controls, and necessary errors or job status. A row runs its own archived configuration and supported launch/weather/integrator options. Double-click opens its stored or completed altitude graph. A completed run belongs to its captured sidecar UUID even if selection changes. Removing a row or importing another document cannot redirect a late completion to another row. No synthetic session row, manual settings selector, settings/provenance block or introductory text remains.

Select motor opens only the bundled catalog. It retains all 1942 native curves and provides whitespace-AND search, manufacturer checkboxes with clear/select all, impulse classes A–O, nominal diameter and length ranges, mount diameter/length limits, hide already-used motors, hide unavailable motors, hide very similar curves, and common-name/designation display. Native `ThrustCurveMotorSetDatabase`, manufacturer aliases, rounded set impulse, availability and `MotorCorrelation` relationships are exported at build time from `core/src/main/resources/datafiles/thrustcurves/initial_motors.db`. Browser predicates retain desktop impulse boundaries, diameter tolerances and nominal/actual mount stops. Similarity applies to the selected motor's native set, retaining the selected curve. Explicit mount dimensions are used; a fit option is disabled when its dimension cannot be resolved. There is no live catalog fetch or update service.

New configuration opens the catalog with a name field. Create configuration atomically adds a UUID configuration, selected mount/motor/delay, verified embedded RSE, and a saved `Simulation N` linked by `<conditions><configid>`. Cancel or invalid curve data changes nothing. The new row is selected automatically. Its initial saved settings are RK4, seed 42, 0.05 s time step, 600 s maximum, vertical 1 m rod with 90° direction, site 28.61°/-80.60°/0 m, average wind 1 m/s with 0.1 m/s deviation and π/2 direction, ISA atmosphere, WGS gravity and spherical geodesy. These are explicit initial settings; existing simulations keep their own settings. Creating a configuration marks existing stored results outdated as observed with the native lifecycle while retaining all stored series.

Rename changes only the configuration name, retaining its UUID and all simulation names, settings, links and data. Delete names the configuration and number of linked simulations, then removes the configuration, every linked simulation and native motor/ignition/recovery/separation reference. Unknown references refuse before publication. Deleting the archived default chooses the first remaining configuration; deleting all leaves an empty list and New can create the first default again. Creation requires an editable single axial stage, an existing body/inner-tube motor mount, and fewer than 16 configurations. Creating mounts, stages, general configuration-dependent component data and full desktop compatibility remain outside this slice.

Simulation sidecar UUIDs are added/removed in the same transaction as archive XML. All surviving UUIDs remain stable. Candidates pass export, codec reimport and view construction before the document Worker publishes them. Requests guard the accepted archive hash. Opaque entries and stored series are preserved, and a bad motor asset or unsupported reference cannot leave a partially created configuration. Exported `.ork` files contain native configurations and saved simulation definitions; browser-computed results still remain separate and are not written over stored results.
