# Account UI and unit preferences

The November 20, 2026 request adds account-level Preferences using the desktop screenshots. The user chose UI and Units first; the other desktop tabs remain outside this increment (ADR-33). Preferences are personal presentation settings, separate from rocket ownership, sharing, archives and physics inputs.

## Page and defaults

The signed-in account navigation opens Preferences and remembers the current rocket/library path for Cancel or OK. UI has Dark, Dark high-contrast and Light themes, scale 0.5–2, font size 5–25, Light/Regular/Medium/Bold font weight and character spacing -20–30 (hundredths of an em). A sample panel previews draft values without applying them globally. Apply saves and updates the page; Cancel discards changes since the last successful Apply; OK saves and returns. No restart is required. Scale multiplies the base font size, with the desktop's minimum effective size of 8 pixels, and scales relative text/control dimensions rather than browser zoom. Existing fixed drawing/window dimensions remain responsive web layouts.

Initial account defaults retain the current web UI (Dark, 14 pixels, scale 1, Regular, zero spacing, metre rocket dimensions). Other unit defaults start metric. Default metric/imperial buttons use actual desktop `UnitGroup` presets, including centimetre metric rocket dimensions, millimetre metric motors, inches/feet/ounces for imperial, and the desktop's Newton/Ns/mbar defaults in both presets.

The native unit choices/presets are exported by `PreferenceUnitsExporter.java` during the existing component metadata build. Generated JSON remains under ignored `web/app/build/components/`; no Java process or mutable Java unit preferences are used in production. Existing conversion precision for already-supported field units is retained; additional density/angle choices use exported factors. Component XML angles remain degrees, whereas native angle factors use radians, so that boundary converts explicitly. Fractional-inch defaults use decimal values in web inputs; nautical miles use exactly 1852 metres.

Available defaults apply to rocket drawing/dimension fields; mass and material density fields/measurements; motor diameter/length, mount information, length filters and impulse; flight altitude/distance, graphs and independent velocity displays. Each component field retains its existing independent unit override during the editor session. Rocket dimensions and flight distance are independent for signed-in accounts. Anonymous/browser-local use retains the prior metre editor and coupled manual simulation-length selection. Preferences are loaded before a hosted rocket opens and apply on subsequent opens/reloads; another tab does not automatically adopt a newly saved setting.

All 23 desktop unit-group selections and the secondary-stability visibility flag are saved. The Units page marks quantities not yet displayed in current web views, including stability margins, acceleration, force, inertia, roughness, area, roll rate and launch/weather coordinates/conditions. Saving their defaults does not add those views, change simulation setup or imply desktop parity. CG/CP positions continue to use rocket dimension units. General, Files, Design, Simulation, Warnings, Launch and Graphics tabs are not populated with nonfunctional placeholders.

## Storage and access

Migration `0004_preferences.sql` adds a versioned JSON row per user with a cascading user foreign key. Existing users need no backfill. Missing rows use the documented defaults. The GET/POST `/api/account/preferences` endpoint always derives the account from its live session; supplied account IDs cannot address someone else's row, including for administrators. Temporary administrator setup must finish first. Responses are `no-store`. POST enforces the configured same origin and existing 16 KiB JSON limit, exact preference keys, native unit membership and finite numeric bounds.

A conditional D1 upsert checks the expected version, active account and current unexpired session in one SQL statement. Concurrent tabs cannot silently overwrite each other: one wins and the stale save returns 409, preserving its page draft for review/reload. No preferences enter a Durable Object, shared command, simulation provenance or exported `.ork`. Changing defaults alone preserves exact archive bytes and the shared document token.
