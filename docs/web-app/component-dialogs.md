# Desktop-style component dialogs and individual units

The subsequent [motor-mount follow-up](motor-mount-controls.md) (ADR-31) replaces this milestone's link-only Motor tab with body/inner tube mount, overhang and ignition editing.

The user's body tube, nose cone and fin screenshots authorize replacing the default archive-field grid with desktop-style component dialogs and giving every measured input its own units. The parts library is explicitly excluded. ADR-25 supersedes ADR-24's default presentation and individual-Apply behavior for the new tabs; the raw archive editor and proven tube controls remain available under Advanced.

## Interface and scope

The dialog has a component-name header, compact tab strip, aligned numeric spinners with adjacent unit selectors/sliders, grouped material controls, and Cancel/OK. Body tubes expose length, outer diameter, inner diameter, wall and automatic/filled controls. Nose cones expose native shape choices, parameter, length, base diameter, wall and flip controls, plus a Shoulder tab. Fin sets expose count, cant, supported planform dimensions, derived sweep angle, section, thickness, placement/rotation, material and root fillets, plus a Fin tabs tab. Elliptical/freeform fins retain their applicable controls; this does not add a freeform point editor, split/convert commands or new rendering/flight support.

Override, Appearance and Comment tabs edit the corresponding supported native scalar fields. Appearance covers the existing line/color archive values; 3D appearances/decals remain preserved. The Motor tab opens the existing Motors & Configuration workspace rather than pretending to implement nested motor-mount settings. Other component types use the same compact field/group layout with their existing scalar fields. Native constructors, enum labels and bundled material choices are exported at build time from the pinned desktop classes. Selecting a material changes its name/density and any existing native material attributes together. Custom names/densities/shear moduli remain editable. No parts-library UI, runtime JVM, dependencies or service is added.

The body tube's established intrinsic mass is shown when available. Other per-component mass projections and draft mass/geometry previews are not introduced; the drawing/calculations update after OK. Existing unsupported-input explanations and the earlier geometry/physics boundaries continue to apply.

Cancel, Escape and the close button discard pending tab/name edits. OK submits them as one accepted-document command. Tabs keep drafts while switching. Advanced retains the earlier individual-Apply workflow and original quick-control proofs. Applying an Advanced edit refreshes the accepted document and clears the other tab drafts; simply inspecting it or changing units does not write the document. Dialog action buttons remain outside the scrolling property panel, including on short screens.

## Units and archive contract

Each dimensional value has an independent selector, including values/attributes in Advanced and the legacy quick controls. Counts, shape parameters, coefficients, color channels, enums and text have no invented physical units. Length supports mm/cm/m/km/in/ft/yd/mi; angles support degrees/radians; mass supports mg/g/kg/oz/lb; density supports the appropriate bulk/surface/line units; shear modulus supports Pa/kPa/MPa/GPa/psi; delays support ms/s/min. Field dimensions are explicitly mapped, not inferred by evaluating imported text. Archive angles remain degrees and other quantities retain their native SI representation. Inch/foot/yard/mile and international avoirdupois mass conversions use their exact SI definitions; existing native approximations for some imperial mass/density factors are not copied into the UI.

The session remembers unit choices per component/control. The workspace length selector supplies the initial length choice; choosing units in one field leaves the others independent. No preferences or unit selections are written into the archive. Each draft retains its full canonical value separately from its formatted display. Unit changes reformat that value and do not round-trip it, dispatch a mutation, mark a result stale or lose a pending numeric edit. Invalid/special values stay text rather than becoming zero during unit conversion. Automatic/filled tokens remain explicit in Advanced.

Diameter controls convert to stored radii, inner diameter edits derive wall thickness using the native relationship, and sweep angle derives/stores sweep length using the native 89° limit. Existing BodyTube clamps/ring-refusal checks are reused. These mappings do not replace the Java engine or claim arbitrary setter-effect parity.

The new `componentProperties` action captures archive hash, component UUID, original field index/name, and all changed values/attributes. A private candidate applies the edits, optional name change, archive export/reimport and complete view construction before publication. Invalid/stale commands retain the entire accepted document. A finite allowlist permits adding/removing the optional scalar fields needed by these tabs: overrides/flags, comments/style, fin tabs/fillets, shoulder dimensions/flags and the displayed native shape/finish fields. Existing known setters validate additions. IDs, arbitrary XML names and nested containers remain protected. Fin-tab legacy/current offset representations now stay synchronized, as the existing position/count/angle aliases do. Physical edits retain historical data/settings/assets and invalidate previously current results under ADR-24's contract.
