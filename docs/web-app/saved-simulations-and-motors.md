# Selected simulations and bundled motors

The November 19, 2026 follow-up authorizes selecting and running saved simulation rows, reading their archived configuration links, opening graphs on double-click, and exposing all bundled motor options. The user additionally chose saved launch/weather settings where supported, with visible refusals elsewhere. This supersedes the earlier session-only configuration/catalog UI restrictions only for this bounded local workflow; accounts, shared storage, deployment, structural editing and general simulation parity remain deferred.

Each saved row uses its sidecar UUID and `<conditions><configid>` link. The table displays the linked motor label and stored summaries. Double-click or Plot opens altitude/time curves from either preserved stored branches or that row's browser result. Stable `time`/`altitude` keys and the older `Time`/`Altitude` labels are recognized; other columns and expressions are never evaluated. Results remain in browser memory, separate from the original stored series and .ork exports. A run captures the chosen row/configuration/options; changing rows does not redirect its completion. Current/stale checks still bind archive bytes, sidecar, engine, catalogs and options. Session flight remains available for the original bounded manual RK4/RK6 workflow.

Saved runs reconstruct launch rod/site, average pink-noise wind, ISA/extended ISA atmosphere, WGS gravity, geodesy, time step/duration, seed, integrator and supported recovery warnings through native Java options and `toSimulationConditions()`. Fixed seeds are retained; a missing seed uses the displayed deterministic seed 42 without changing the archive. Supported bounds include 0.001–1 s steps, up to 3600 s duration, rods up to 100 m and angles within the core's ±60° range. Active multilevel wind, constant gravity, lookups, extensions, unknown/ambiguous settings and unsupported model graphs refuse explicitly. Inactive multilevel wind data is preserved when the saved active model is Average. A saved row never silently falls back to the manual session settings.

The source motor list is `core/src/main/resources/datafiles/thrustcurves/initial_motors.db`: 1528 motors and 1942 curve options. `metadata.json` in the same directory records the database version and update URL (`https://openrocket.github.io/motor-database/motors.db.gz`). This workflow uses the pinned local database; it does not fetch updates from that service. The build-time Java exporter calls the desktop SQLite reader and RSE writer, including every curve and native delay choice. The generated index and content-addressed RSE assets are ignored build outputs, regenerated by predev/prebuild. All options appear in a searchable, manufacturer-filtered, paginated picker. Curves load from same-origin assets when needed and are SHA-256 checked. Exact catalog references can also resolve missing embedded curves, while the earlier two exact legacy references retain their established handling.

Applying a catalog choice explicitly selects an existing body/inner-tube mount and configuration. The document Worker validates the full archive hash, catalog identity, motor fields and delay; changes only the target motor XML; marks only stored results linked to that configuration outdated; embeds the chosen RSE; and reimports the candidate before publication. Other configuration links, settings, series, opaque XML, attachments and the archived default remain intact. No-op assignments preserve original bytes. Unsupported/ambiguous motor data and conflicting same-digest headers refuse without publishing. Creating mounts/configurations is outside this increment.

The core source pin and existing digest checks remain intact. A full motor list does not certify every rocket/motor combination or numerical parity for every curve. The browser engine still accepts only the documented bounded graph.
