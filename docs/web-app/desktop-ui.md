# Desktop-style browser workspace

The later [selected-simulation and full motor picker follow-up](saved-simulations-and-motors.md) supersedes the configuration/catalog/settings limits below for its authorized local slice. This record retains the earlier implementation and verification history.

The November 19, 2026 user request authorizes restyling the existing browser editor to match the supplied desktop OpenRocket screenshots: design, motors/configuration, flight simulations, component editor and motor selector. This is presentation and interaction work within the existing local editor; the engine, archive projection, catalogs and hosting boundaries are unchanged. No deployment or push is authorized.

The workspace uses a dark desktop palette, compact menus and controls, three keyboard-accessible tabs, component tree and original desktop component icons. The exterior drawing remains below every tab, with fit/zoom, units and synchronized session configuration selection. Its SVG viewport follows the canvas aspect ratio and uniformly scales the existing Java polygons to fit; it does not stretch the rocket. Component properties open in a modeless dialog through Edit or a double-click; Escape/Close dismiss it and restore focus. Each existing Apply action commits its field independently; closing discards unapplied drafts. The modeless window allows component selection, imports, units and downloads while editing.

Motor configurations appear in a table. Select motor opens a searchable chooser of configurations already in the archive; Cancel leaves the selection unchanged and OK selects it for this browser session. It does not change the motor assignment or archived default. Unsupported structural tools and component creation remain disabled with explanations; the full desktop motor catalog and editing motor assignments are outside the existing supported model. The simulation table distinguishes imported unverified statuses from the current or stale session flight; imported numerical columns remain blank because the browser projection does not expose those stored summaries. No numerical results are invented. The simulation component stays mounted while tabs change so switching views retains a running worker and session results.

Only the established exterior polygons are drawn; internals, whole-rocket stability and 3D are not added by this UI change. Component measurements exclude mass/CG overrides and motors as before. Existing unsafe-edit refusal, archive preservation and original upload handling remain intact. Phone layouts retain the tree and editing while hiding the unavailable component palette.

## Validation

The existing browser tests now enter through the File menu, component editor and flight tab. Their numerical tolerances and archive/desktop assertions are unchanged. `test/desktop-ui.mjs` adds the affected workspace interactions: tab keyboard navigation, persistent drawing, icon loading, zoom, component double-click/Escape/focus restoration, motor search/cancel/apply, selector synchronization, byte-identical export after configuration selection, flight completion across tabs and a phone viewport. It runs with the existing acceptance suite and writes `desktop-ui-report.json` and screenshots to ignored `web/app/build/gp/`.
